01 — DIRECTORY POLICY

ルート直下の整理方針

2026年8月30日時点のルート直下を上から確認し、公開情報として残すもの、正本へ寄せるもの、非公開・削除候補に分けました。

対象扱い理由・作業方針
index.html / trillionbank/公開の正本会社・事業・ニュース・問い合わせ導線はこの構成を正規ページとして扱います。
_tbnews/新しい記事の正本今後のブログ・お知らせ・HackⅡレポートはここに追加します。旧記事群とは分けて管理します。
_includes/ / _layouts/ / _data/運用基盤共通ヘッダー、フッター、記事テンプレート、事業データを管理します。変更時は全ページへの影響を確認します。
assets/ / images/ / logo/公開アセット画像・CSS・ロゴを管理します。使っていない画像は別途棚卸ししてから整理します。
llms*.txt / knowledge.json / ai-patch.json / site-structure.jsonAI向け正規情報AI検索・LLMエージェントに読ませる一次情報です。HackⅡの最新提供範囲と矛盾しないよう更新します。
robots.txt / sitemap*.xml / feed.xmlクロール誘導検索エンジン、AI検索クローラー、フィード読者に正規ページを渡します。旧記事の露出は新しい正本へ寄せます。
_news/ / news/旧アーカイブ扱い古いブランド表現・古い価格・古いスコア表現が混在しているため、新規導線・サイトマップ・AI向けファイルから外します。
about/ / business/ / company/ / contact/ / enterprise/ / talent/ / works/移行候補旧URLや補助ページが含まれます。正規URLは /trillionbank/ 配下へ寄せ、必要なものだけリダイレクト・統合します。
docs/ / tools/ / scripts/ / .github/内部運用レポート生成、IndexNow、llms.txt生成、デプロイのための作業領域です。顧客向け公開情報とは分けて扱います。
_regalis-backup/ / AIO-Hack2_package/ / admin/ / verify/ / scan.html / scan-simulator.html / ai-coupon-system/非公開・削除候補検証用・旧資料・内部ツールが含まれます。削除は参照元確認後に行い、当面は公開導線とクロール対象から外します。
node_modules/ / vendor/ / screenshots/ / .playwright-mcp/ビルド不要依存ファイルや検証結果です。公開サイトには不要なのでビルド対象外にします。

大きな削除は、公開ページ・スクリプト・過去のリンクを壊す可能性があります。まず「新しい正本へ誘導し、旧情報をAI・サイトマップ・フィードから外す」形で反映し、物理削除は参照元確認後に進めます。

03 — AI SEARCH ACTIONS

AI向けの実装施策一覧

ENTITY

会社・サービスの正規情報

Organization、Service、SoftwareApplication、Product、FAQPage、Article、BreadcrumbListをJSON-LDで整備し、会社・サービス・FAQ・記事の関係を明確にします。

LLM FILES

llms.txt と詳細ファイル

ルートの llms.txt に要約と重要リンクを置き、llms-full.txt、モデル別llms、knowledge.json、site-structure.jsonへ接続します。

CRAWL

クロール方針

検索に必要なクローラーは許可し、学習専用クローラーは方針に応じて制御します。重要ページはサイトマップ・内部リンク・更新日で見つけやすくします。

CONTENT

AIが答えやすい本文構造

H1-H3、定義文、FAQ、比較表、料金条件、対象外条件、注意書きを見える本文として配置します。隠しテキストや本文と矛盾する構造化データは使いません。

MEASURE

AI流入と問い合わせ前行動

AI系参照元・UTM・ai_source付き来訪を検出し、フォーム・商談予約クリックまでをGA4イベントとして記録します。

REMEASURE

再計測レポート

施策前後で同じ質問・同じ競合・同じ条件を使い、回答本文、引用URL、候補入り、競合差、問い合わせ前行動の変化を比較します。

構造化データは、ページ本文に見えている内容と一致している必要があります。AIや検索での表示を保証するものではなく、正規情報を読み取りやすくするための基盤として実装します。

04 — HACKII PACKAGE

HackⅡパッケージに含めるサービス範囲

HackⅡはSaaSの画面だけを売るのではなく、測定、実装、再計測、販売代理店支援までを組み合わせるService-led SaaSとして提供します。

  • AI Search Audit現状のAI回答、競合の候補入り、引用URL、誤情報、AI流入の有無を監査し、最初の改善優先度を出します。
  • Technical FoundationJSON-LD、llms.txt、knowledge.json、site-structure.json、robots.txt、sitemap、フィード、SSR/SSG、見出し階層を整備します。
  • Content & FAQ重要質問に対応するFAQ、比較記事、サービス定義、料金条件、対象外条件、導入事例、外部掲載用の一次情報を作成します。
  • AI Referral MeasurementAI系参照元、UTM、問い合わせフォーム、商談予約クリックをつなぎ、マーケターが見られる月次データにします。
  • Citation & PR Backlog自社サイトだけでなく、比較メディア、業界メディア、ニュース、レビュー、販売代理店ページの整備優先度を出します。
  • Partner Enablement販売代理店・運用パートナー向けに、共同提案資料、顧客説明文、月次レポート説明、施策進行管理の型を提供します。

06 — DELIVERY CHECKLIST

納品前チェックリスト

  1. 新規ページのタイトル、説明文、H1、パンくず、CTAが公開目的と一致している。
  2. JSON-LDが有効なJSONで、本文にない内容や成果保証を含んでいない。
  3. llms.txt、llms-full.txt、knowledge.json、ai-patch.json、site-structure.jsonの主要URLが一致している。
  4. サイトマップ、ニュースサイトマップ、フィードに旧記事ではなく新正本が載っている。
  5. 顧客向けのHackⅡ導線では、代理店表現が「販売代理店」に統一されている。
  6. 「必ず表示される」「必ず引用される」「売上を保証する」といった断定表現がない。
  7. フォーム、商談予約、問い合わせの導線が画面上で見える。
  8. PCとスマートフォンで、表・ボタン・見出しの文字がはみ出していない。
  9. 公開前にサイト全体のビルド、JSON検証、構造化データ抽出確認を行っている。
  10. 公開後にサイトマップ送信、IndexNow送信、主要URLの表示確認を行っている。
07 — IMPLEMENTATION STANDARD

実装時の基準

構造化データはJSON-LDを基本とし、ページ上に見えている内容と一致させます。Googleの検索用クローラーと学習専用クローラーは役割が異なるため、検索・発見に必要なページは許可し、学習専用の利用は方針に沿って制御します。llms.txtは、AIエージェントが最初に読む軽量な案内ファイルとして、ルートに短い要約と重要リンクを置きます。

FAQ

よくある質問

このページは顧客向けですか、外部エンジニア向けですか？
両方です。顧客にはHackⅡの提供範囲を伝え、外部エンジニアにはどのファイルを作成・更新すべきかを伝える公開版マニュアルとして使います。契約条件や顧客個別データは含めません。
旧記事や古い情報は削除済みですか？
大きな物理削除は参照元確認後に行います。まず公開導線、サイトマップ、フィード、AI向けファイルを新しい正本へ寄せ、古い情報がAIに優先参照されないようにします。
GEO対策では何を納品しますか？
AI検索現在地監査、質問セット、Win/Lossレポート、引用チャネル分類、AEO/GEO/SEO改善バックログ、JSON-LD、llms.txt、knowledge.json、site-structure.json、FAQ、AI流入計測、再計測レポートを、契約範囲に応じて納品します。
AI検索での表示や問い合わせは保証されますか？
保証しません。HackⅡが約束するのは、同一条件での測定、回答本文・引用URL・日時・条件を含む証拠保存、改善優先度の提示、施策後の再計測です。
