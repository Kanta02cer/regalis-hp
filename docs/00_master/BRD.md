## 1. 背景と事業目的

### 1-1. 市場背景

2024年以降、ChatGPT・Gemini・Perplexity等の生成AIが「検索エンジン」に取って代わりつつある。
ユーザーの情報収集行動の変化に伴い、企業にとって「AIに正しく引用されること」が新たなマーケティング競争軸になっている。

**課題：**
- AIがWebサイトをクロール（学習・参照）していても、企業側にはそれが見えない
- AIに引用されているかどうかが計測できない
- AIクローラーへの最適化手法が体系化されていない
- AIクローラーによるサーバー負荷・無断学習利用を制御できない

### 1-2. Regalis Groupの事業目的

**HackⅡ（ハックツ）** は、上記の課題を解決するB2B SaaSプラットフォームとして開発する。

| 事業目標 | 指標 | 目標値 |
|---------|------|--------|
| 有料契約顧客数 | 導入企業数 | リリース6ヶ月後 50社 |
| 月次経常収益 | MRR | 6ヶ月後 ¥5,000,000 |
| AI引用改善実績 | 顧客AICS™スコア平均 | 80pt以上（Aグレード） |
| Pay per Crawl | AI事業者からの収益 | Phase 3リリース後 ¥1,000,000/月 |

### 1-3. 競合優位性

| 観点 | 競合（SEO/AIOツール） | HackⅡ |
|------|---------------------|--------|
| 計測対象 | 検索順位・バックリンク | AIクローラー・AI引用 |
| 収益モデル | SaaS月額のみ | SaaS + Pay per Crawl（二重収益） |
| 自動化 | スコア提示のみ | スコア連動型自動パッチ生成 |
| 特許 | なし | AICS™スコアリング・クローラー識別配信（出願中） |

## 2. システム全体像

### 2-1. 4機能の関係

```
[AIクローラー（GPT/Claude/Gemini/Perplexity等）]
         |
         | クロールリクエスト
         ↓
┌─────────────────────────────────────────────┐
│           HackⅡ プラットフォーム             │
│                                             │
│  [Tsukull（ツクル）] ← ポリシー判定          │
│    allow / block / throttle / allow_optimized│
│         |                                   │
│         ↓ 通過したクロール                   │
│  [Hackall（ハカル）] ← 計測・ロギング         │
│    モデル別/ページ別/時系列 で記録             │
│         |                                   │
│         ↓ 計測データを基に                   │
│  [Misell（ミセル/AIパッチ）] ← パッチ生成     │
│    AICS™スコアリング + 最適化ファイル自動生成  │
│         |                                   │
│         ↓ 課金APIキー確認                   │
│  [Pay per Crawl] ← マネタイズ               │
│    クロール数に応じてAI事業者に課金           │
└─────────────────────────────────────────────┘
         |
         ↓ 最適化されたコンテンツを配信
[顧客Webサイト]  ←→  [HackⅡ ダッシュボード（顧客が確認）]
```

### 2-2. ユーザーロール定義

| ロール | 具体的なユーザー | 主な操作 |
|--------|----------------|---------|
| **管理者（Regalis）** | 井上幹太（代表）・社内運用担当 | 全機能の設定・顧客管理・収益確認 |
| **顧客（コンテンツ提供者）** | HackⅡ導入企業の担当者 | ダッシュボード閲覧・制御設定・収益確認 |
| **AI事業者** | OpenAI / Anthropic / Google 等のAPI担当 | APIキー管理・課金確認・利用規約遵守 |
| **開発・保守担当** | 委託先エンジニアチーム | 機能開発・バグ修正・インフラ管理 |

| 全体 | 可用性 | 99.9% SLA（月間ダウンタイム ≤ 43分） | 監視ツール |

## 4. 制約条件

### 4-1. 技術制約

| 制約 | 内容 | 理由 |
|------|------|------|
| エッジ処理 | Hackall / Tsukull はCloudflare Workers推奨 | 低レイテンシ・グローバル対応 |
| DB | PostgreSQL（メイン） + Redis（キャッシュ/レートリミット） | 既存スタックとの統合 |
| 既存サイト | Jekyll / GitHub Pages との連携が必須 | 顧客サイトがSSG主体 |
| API設計 | RESTful API（OpenAPI 3.0準拠） | ドキュメント自動生成のため |

### 4-2. 法的制約

| 法規制 | 対応方針 | 詳細 |
|--------|---------|------|
| 個人情報保護法 / GDPR | IPアドレスはハッシュ化。生IP保持禁止 | `legal_compliance.md` 参照 |
| 不正競争防止法 | クローラーブロック機能の設計に注意 | 正当な業務制限として記録 |
| 特許出願中技術 | AICS™スコアリング・クローラー識別配信の実装は秘密保持必須 | NDA要 |
| robots.txt 倫理規範 | Disallow指定は法的強制力なし。ブロックはゲートウェイ層で実装 | `legal_compliance.md` 参照 |

### 4-3. 予算・納期制約

| フェーズ | 対象機能 | 納期目標 | 予算枠 |
|---------|---------|---------|-------|
| Phase 1 | Hackall（計測基盤） | 2026-08-31 | 別途協議 |
| Phase 2 | Tsukull + Misell | 2026-11-30 | 別途協議 |
| Phase 3 | Pay per Crawl | 2027-03-31 | 別途協議 |

## 5. 前提条件・依存関係

- Hackall の完成が Phase 2・3 の全機能の前提となる（計測データが他機能のインプット）
- AI事業者（OpenAI / Anthropic 等）との課金契約交渉は Regalis が担当。エンジニアは技術実装のみ
- ドメイン・DNS設定・SSL証明書はRegalisが管理
- 顧客サイトへの計測タグ設置は顧客自身が行う（導入マニュアルを委託先に作成依頼）
