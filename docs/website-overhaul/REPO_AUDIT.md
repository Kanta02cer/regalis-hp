# Repository audit

Audit date: 2026-09-05

## Executive finding

The site already has a substantial Jekyll content base, but public entity facts, product stage, prices, structured data, internal development files, and auto-generated AI files are not consistently governed. Authority work should begin with factual consistency and removal of private source material, not with mass article generation.

## High-priority findings

| Finding | Risk | Action |
|---|---|---|
| Public repository contains agent memory, browser logs and documents labelled confidential | disclosure and operational risk | remove from current tree, add ignore rules, review Git history and rotate exposed credentials |
| HackⅡ page contains old prices and unverified service claims in visible copy and JSON-LD | customer confusion and structured-data mismatch | rewrite without public prices and separate current scope from analysis/roadmap |
| Shared Organization schema contains old Regalis relationship, old address wording and unapproved media entries | entity inconsistency | generate schema from approved public facts only |
| Article layout repeats old entity data and LocalBusiness markup | inconsistent knowledge graph | use Organization, Person, Article and Breadcrumb only where supported |
| Multiple machine-readable AI files can drift from visible pages | stale or contradictory claims | keep a small canonical set and generate from approved content |
| Existing content covers overlapping AEO/GEO/LLMO queries | cannibalization and thin duplication | maintain a content map and consolidate before creating articles |
| `llms.txt` is generated by workflow | manual changes are overwritten | modify generator and source data, not only generated output |

## Technology and operating model

- Jekyll / GitHub Pages
- Liquid includes and layouts
- corporate pages under `trillionbank/`
- articles under `_tbnews/`
- shared data under `_data/`
- GitHub Actions for deployment, IndexNow and machine-readable files

## Immediate public-content priorities

1. public facts and publication guard;
2. remove internal files from public HEAD;
3. correct global schema, address and product stage;
4. remove old HackⅡ price / offer markup;
5. add an insights hub and methodology content;
6. validate redirects, robots, sitemap and generated files;
7. establish browser and release evidence.

## History warning

Deleting files in a new commit does not remove them from Git history. If credentials, personal information, contracts, unpublished patents, or other confidential data were committed, move the source materials to a private repository, rotate credentials, and use a separately approved history-rewrite process.
