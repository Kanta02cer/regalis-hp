# Feature 02: Pay per Crawl — 課金ロジック・ビジネス仕様

> 機能コードネーム: PPC  
> 役割: AIクローリングをAPI課金に変換するマネタイズ基盤  
> 優先度: Phase 3  
> 作成日: 2026-05-25 | バージョン: 1.0

---

## 1. 機能概要

### 1-1. コンセプト

「AIに読まれること」をそのまま収益に変換するアドセンス型モデル。

```
従来モデル:
  コンテンツ公開 → AIがクロール → AIが回答 → ユーザーが来訪 → 広告収益
                                   ↑ この段階では無収益

Pay per Crawlモデル:
  コンテンツ公開 → AIがクロール → [APIゲートウェイが課金] → AIが回答
                                   ↑ クロール時点で課金発生
```

### 1-2. ビジネスモデル全体像

| 役割 | エンティティ | 説明 |
|------|------------|------|
| **コンテンツ提供者** | HackⅡ導入サイト（顧客） | コンテンツを公開し、クロールされるたびに報酬を受け取る |
| **プラットフォーム** | Regalis Japan Group（HackⅡ） | APIゲートウェイ・精算・分配を管理する |
| **AI事業者** | OpenAI / Anthropic / Google 等 | APIを通じてコンテンツアクセスし、課金される |

**収益分配:**
- AIクローラーが支払う課金の **70%** → コンテンツ提供者
- **30%** → HackⅡプラットフォーム手数料

---

## 2. 課金モデル定義

### 2-1. 課金単位（プライシングティア）

| ティア | 対象 | 課金単位 | 単価（目安） | 備考 |
|--------|------|---------|------------|------|
| **Micro** | 汎用クローラー（CCBot等） | 1クロール / ページ | ¥0.01〜¥0.05 | 学習用・低付加価値 |
| **Standard** | 主要AIモデル（GPT / Gemini / Claude） | 1クロール / ページ | ¥0.5〜¥2.0 | 推論型・高付加価値 |
| **Premium** | 企業向けAPIアクセス | 1,000トークン | ¥0.1〜¥0.5 | 構造化データ取得 |
| **Subscription** | AI事業者との年間契約 | 月額定額 | 別途交渉 | 大量アクセス向け |

**初期フェーズでの実装優先順位:**
1. Standard（主要AIモデル）の従量課金
2. Micro（汎用クローラー）の従量課金
3. Subscription（大量アクセスへの対応）

### 2-2. 課金計算ロジック

**1クロールあたりの課金額（Standard）:**

```
基本料金 = ベース単価 × コンテンツ品質係数 × ページ長係数

コンテンツ品質係数:
  AIOスコア 90〜100 → 1.5倍（プレミアムコンテンツ）
  AIOスコア 70〜89  → 1.0倍（標準）
  AIOスコア 50〜69  → 0.8倍
  AIOスコア 〜49    → 0.5倍

ページ長係数:
  本文 5,000文字以上 → 1.3倍
  本文 2,000〜4,999文字 → 1.0倍
  本文 2,000文字未満 → 0.7倍
```

**計算例:**
```
記事「LLMOとは」（AIOスコア92点、本文6,000文字）
  ベース単価: ¥1.0
  × 品質係数: 1.5（スコア92）
  × ページ長係数: 1.3（6,000文字）
  = ¥1.95 / クロール
```

### 2-3. 無料クロール枠（フリーミアム設計）

AI事業者のハードルを下げるため、初期は一定量の無料枠を設ける。

| 対象 | 無料枠 / 月 | 超過後の課金 |
|------|------------|------------|
| Googlebot | 無制限（課金対象外） | — |
| 主要AIモデル（GPT/Gemini/Claude/Perplexity） | 1,000クロール / 月 / サイト | Standard料金 |
| 汎用クローラー（CCBot等） | 500クロール / 月 / サイト | Micro料金 |

**理由:** 無料枠内はAIが自由にクロールできるため、AI引用・流入のベースラインを維持する。課金は超過分のみ。

## 3. 精算フロー

### 3-1. 月次精算サイクル

```
月初〜月末: クロールイベントを集計・課金額を計算
    ↓
月末締め: AI事業者へ請求書発行（API経由 or メール）
    ↓
翌月末払い: AI事業者からHackⅡプラットフォームへ入金
    ↓
入金確認後3営業日以内: コンテンツ提供者へ報酬振込（70%分）
```

### 3-2. コンテンツ提供者の収益計算例

```
ある月の実績:
  GPTBot アクセス: 2,500回
  - 無料枠: 1,000回（課金なし）
  - 課金対象: 1,500回
  - 平均単価: ¥1.2 / クロール
  - 課金総額: ¥1,800

  Gemini アクセス: 800回
  - 無料枠: 800回（課金なし）
  - 課金対象: 0回

  月間課金総額: ¥1,800
  コンテンツ提供者への分配（70%）: ¥1,260
  HackⅡ手数料（30%）: ¥540
```

### 3-3. 最低振込額

- 最低振込額: **¥1,000 / 月**（未満は翌月繰越）
- 振込手数料: HackⅡ負担（国内銀行振込の場合）

## 4. AI事業者へのオプトイン設計

### 4-1. 参加フロー（AI事業者側）

```
1. HackⅡ API ポータルにアカウント登録
2. 利用規約・課金規約に同意
3. APIキー発行
4. User-Agentに規定ヘッダーを付与してクロール開始
5. 月次請求書に対して支払い
```

**Pay per Crawl に参加しないAI事業者のクロールは:**
- Hackallで計測・記録はされる
- 課金はされない（ブロックもしない）
- ただし、Tsukull（Feature 03）の設定によっては制御対象になる可能性あり

### 4-2. 課金APIトークン仕様

AI事業者がクロール時に付与する認証ヘッダー：

```http
GET /news/llmo-guide/ HTTP/1.1
Host: example.com
User-Agent: GPTBot/1.0
X-HackII-API-Key: hk_live_xxxxxxxxxxxxxxxx
X-HackII-Crawl-Type: inference
```

| ヘッダー | 必須 | 説明 |
|---------|-----|------|
| `X-HackII-API-Key` | 必須 | AI事業者のAPIキー |
| `X-HackII-Crawl-Type` | 推奨 | `learning` or `inference` |
| `X-HackII-Request-ID` | 推奨 | 重複除去用のリクエストID |

## 5. 不正対策・エラー処理

### 5-1. 不正クロール検知

| パターン | 定義 | 対応 |
|---------|------|------|
| レートボム | 1分間に100件超のクロール | 自動スロットリング |
| APIキー悪用 | 複数IPからの同一キー使用 | キー停止・アラート |
| ユーザー偽装 | 人間に偽装してコンテンツを取得 | ログ記録のみ（Phase 3以降で対策） |

### 5-2. 課金ロジックの冪等性

ネットワーク障害等による二重送信を防ぐため：
- `X-HackII-Request-ID` が同一のリクエストは24時間以内なら重複除去
- クロールイベントテーブルに `request_id` のユニーク制約を設ける

## 6. 受け入れ条件

- [ ] 無料枠・超過課金の計算が仕様通りに動作すること（単体テスト必須）
- [ ] 課金金額の計算ロジックが変更されてもコード修正なしに対応できること（設定ファイル化）
- [ ] AIクローラー1件分の課金計算をAPIが100ms以内に完了できること
- [ ] 月次精算レポートCSVがダッシュボードからダウンロードできること
- [ ] 冪等性テスト：同一request_idを10回送信しても課金が1回のみ記録されること
